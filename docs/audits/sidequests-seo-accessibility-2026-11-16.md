# SideQuests SEO and accessibility audit

- **Audit date:** 2026-11-16
- **Production origin:** <https://sidequestsofficial.vercel.app>
- **Scope:** deployed public pages and shared shell, raw HTTP HTML for normal and Googlebot user agents, sitemap/robots, plus axe-core browser scans.

## Executive summary

The deployed site serves content-bearing HTML for its principal discovery pages, and ordinary visitors and Googlebot received the same HTTP statuses in the sampled routes. The largest SEO risks are stale crawler documents that point entirely to the previous `watchtopia.akimbolabs.site` hostname, missing canonical/social metadata, and unknown movie IDs returning HTTP 200. The largest accessibility risks are invalid autocomplete ARIA, an unnamed icon-only menu button, and missing/duplicated page landmarks on list/detail templates.

This is an audit of the deployed snapshot, not a claim of WCAG certification. It does not include a full screen-reader session, a complete crawl of every route/ID, or manual color measurement under every image/background composition. The live-site findings below are point-in-time observations; test and search code changed locally during the work but had not yet been deployed at the time of the audit.

## Accessibility findings

Automated scan used **axe-core 4.14.0** through Playwright with tags `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, and `best-practice`. It scanned the live home, popular Movies, popular TV, Anime, Cartoons, Library, and Fight Club detail pages at a 1365×900 viewport, plus Library at 390×844. These are automated findings, not a substitute for manual assistive-technology testing.

| Priority | Finding                                                                                                       | Evidence / affected templates                                                                                                                                                                                                                  | Recommended action                                                                                                                                                               |
| -------- | ------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **P1**   | Autocomplete uses `aria-expanded` on a plain textbox role; axe reports `aria-allowed-attr` (critical impact). | Repeated on all sampled routes; the shared search input has `aria-autocomplete="list"`, `aria-expanded`, and `aria-controls`, but no combobox role.                                                                                            | Implement a valid combobox/listbox pattern, including keyboard navigation and active option semantics, or remove unsupported attributes. Verify with keyboard and screen reader. |
| **P1**   | The icon-only navigation/menu trigger has no accessible name; axe reports `button-name` (critical impact).    | Repeated in desktop and mobile scans; selector `.size-10` maps to the menu drawer trigger in the shared header.                                                                                                                                | Give the button a concise accessible name such as “Open navigation menu”; ensure expanded/collapsed state remains announced.                                                     |
| **P1**   | Browse/detail templates do not consistently expose one main landmark.                                         | Axe reported `landmark-one-main` on `/movie/popular`, `/tv/popular`, `/anime`, `/cartoons`, and `/movie/550`.                                                                                                                                  | Ensure exactly one page-level `<main>` per route and place primary route content inside it.                                                                                      |
| **P2**   | Repeated/indistinguishable banner landmarks.                                                                  | `landmark-no-duplicate-banner` and `landmark-unique` on movie/TV/anime/cartoon browse routes; the site shell header and route intro both render as top-level headers without distinct labels.                                                  | Keep the global banner landmark unique; use a section or properly labeled header for the route intro.                                                                            |
| **P2**   | Browse content falls outside landmarks.                                                                       | Axe `region` rule reported 60 nodes on `/movie/popular` and 142 on `/cartoons`; sampled examples include media-card artwork and text.                                                                                                          | Group each content rail/grid in a named section or other appropriate landmark; avoid adding excessive redundant landmarks.                                                       |
| **P2**   | Misapplied ARIA role.                                                                                         | Axe reported `aria-allowed-role` on an `<aside role="status">` in sampled movie/TV/anime/detail routes.                                                                                                                                        | Use a semantically suitable live-region element (for example, a non-landmark status container) or an appropriate aside without the incompatible role.                            |
| **P2**   | Duplicate page-level H1 text.                                                                                 | Raw HTML had two H1s on sampled home, browse, and valid detail routes (site wordmark and route title); Library had one.                                                                                                                        | Make the wordmark a link/span rather than an H1 so each page has one meaningful H1.                                                                                              |
| **P3**   | Muted mobile navigation labels merit manual contrast measurement.                                             | Mobile links use small 9px labels with muted zinc-gray text on a nearly black surface. Axe did not report a color-contrast violation in the sampled scans, but 2 checks were incomplete and the composited backdrop was not manually measured. | Measure contrast at the actual mobile viewport/background and increase label contrast/size where needed. Test keyboard focus visibility and touch targets manually.              |

Positive observations: sampled media images had `alt` attributes; the mobile nav exposes the accessible name “Primary mobile navigation” and visible text labels; the Library has a page-level main landmark. The automated test did not exercise keyboard-only menu operation, screen-reader announcements, zoom/reflow, reduced motion, or the full player/episode flows.

## Test and audit method

- Requested live raw HTML over HTTPS for Mozilla and Googlebot user agents; recorded status, body/head metadata, canonical/social tags, and route-specific content.
- Parsed live `robots.txt` and `sitemap.xml`, including URL hosts, route coverage, and modification timestamps.
- Ran axe-core in Chromium against seven desktop routes and the Library at a mobile viewport. Axe’s reported “impact” is its prioritization label, not a legal/conformance determination.
- Inspected source for shared search/menu controls and page-shell landmarks. No account was signed into, no watchlist was modified, and no user data was submitted.
